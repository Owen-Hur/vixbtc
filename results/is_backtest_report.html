테스트한 4가지 전략

A. slope_change 단독 Best Return
방향: slope_change > 0 → Short, slope_change < 0 → Long
레버리지: |slope_change| 크기 4단계 — Q1: 0.5x, Q2: 1.0x, Q3: 1.5x, Q4: 2.0x
HMM: 미사용
결과: 총수익 +467%, Sharpe 2.147, MDD -68%
B. HMM 단독 (Champion theta) Baseline
방향: HMM Soft Leverage가 결정 (Normal→Long, Fear→Short)
레버리지: Lev = P(N)×1.5 + P(A)×0.5 + P(F)×(-0.5)
slope: 미사용
결과: 총수익 +94%, Sharpe 0.772, MDD -37%
C. 통합 Scale (slope 방향 x HMM 스케일링) Failed
방향: slope_change가 결정
레버리지: slope 레버리지 × HMM 스케일 팩터
  scale = P(N)×1.0 + P(A)×0.5 + P(F)×(-0.3)
실패 원인: Fear 구간에서 scale이 음수 → slope 방향이 반전 → 양쪽 다 틀림
결과: 총수익 -8%, Sharpe -0.076, MDD -69%
D. 통합 Cap (slope 방향 + HMM 레버리지 상한) Adopted
방향: slope_change가 결정 (A와 동일, 절대 변경 안 함)
레버리지: slope 레버리지를 HMM 상태별 상한(Cap)으로 제한
  Normal → cap 2.0x (slope 그대로)
  Alert → cap 1.0x (slope 1.5x/2.0x여도 1.0x로 축소)
  Fear → cap 0.5x (최소 레버리지로 제한)
핵심: slope의 방향 판단은 건드리지 않고, HMM은 "위험할 때 크기만 줄이는" 역할
결과: 총수익 +104%, Sharpe 0.811, MDD -66%

최종 채택 구조

slope_change ──→ 방향 + 기본 레버리지 결정 │ HMM 상태 ──→ 레버리지 상한(Cap) 적용 │ ▼ 오늘의 포지션 진입 │ LSTM-AE ──→ 장중 이상 탐지 시 포지션 교체 (Phase B) │ 15:59 ET 청산

왜 이 구조인가?

1. slope_change의 방향 판단이 이미 유효 (Hit Rate 55.1%, Q4에서 61.9%)
 → HMM이 방향에 개입하면 noise 추가. 건드리지 않는 게 최선.

2. HMM은 방향 예측보다 상태 분류에 강점
 → "위험할 때 노출 줄이기"가 HMM의 자연스러운 역할.

3. 각 모듈이 서로 다른 시간 해상도에서 독립적으로 작동
 → slope(일봉 방향) + HMM(일봉 리스크) + LSTM-AE(분봉 교체). 겹치지 않음.
