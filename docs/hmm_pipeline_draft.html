Phase 1

Feature Engineering

매일 장 시작 전 다음 순서로 계산:

1-1. 변화량 계산 (ΔVIX)

df['ΔVIX_9d']  = df['VIX_9d'].diff()
df['ΔVIX_30d'] = df['VIX_30d'].diff()
df['ΔVIX_3m']  = df['VIX_3m'].diff()
df['ΔVIX_6m']  = df['VIX_6m'].diff()

1-2. PCA 변환 — IS 구간에서 fit 후 고정

⚠️ scaler·pca 객체는 IS에서 한 번만 fit하고 저장. 매일 predict 시 동일 객체 재사용.
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA

delta_cols = ['ΔVIX_9d', 'ΔVIX_30d', 'ΔVIX_3m', 'ΔVIX_6m']

scaler = StandardScaler().fit(is_data[delta_cols])        # → scaler.pkl 저장
pca    = PCA(n_components=2).fit(scaler.transform(is_data[delta_cols]))  # → pca.pkl 저장

transformed  = pca.transform(scaler.transform(df[delta_cols]))
df['pca1']   = transformed[:, 0]   # Level 요인 (96.17%)
df['pca2']   = transformed[:, 1]   # Slope 요인 (3.51%)

1-3. slope 및 delta_slope

df['slope']       = df['VIX_9d'] - df['VIX_30d']
df['delta_slope'] = df['slope'].diff()

1-4. 절대 수준

df['vix_30d_level'] = df['VIX_30d']

최종 Feature Vector

FEATURES = ['pca1', 'pca2', 'delta_slope', 'vix_30d_level']
# slope는 pca2와 심각하게 중복 → 제외

다중공선성 확인 (1회)

from statsmodels.stats.outliers_influence import variance_inflation_factor
# VIF > 5: 주의, VIF > 10: 반드시 제거
Feature 역할 포함 근거
pca1 Level 변화 요인 4개 만기 공통 움직임 압축 (96.17%)
pca2 Slope 변화 요인 논문 핵심, slope와 중복 → slope 대체
delta_slope 기울기 가속도 단기 패닉 가속/둔화 탐지
vix_30d_level 절대 공포 수준 pca1/2가 못 잡는 역사적 극단값
Phase 2

HMM 학습 — State 구조 결정

2-1. IS 전체로 HMM 학습

from hmmlearn.hmm import GaussianHMM

hmm = GaussianHMM(
    n_components=3,
    covariance_type='diag',   # 다중공선성 영향 최소화
    n_iter=200,
    random_state=42
)
hmm.fit(is_features)   # → hmm.pkl 저장

2-2. State 레이블 고정 (필수)

🔴 HMM은 매 학습마다 State 번호가 무작위로 바뀜 — 반드시 후처리 필요

EM 알고리즘의 무작위 초기값으로 인해 같은 데이터로 학습해도 State 0이 공포일 수도, 정상일 수도 있음.

import numpy as np

state_means = []
for k in range(3):
    mask = (hmm.predict(is_features) == k)
    state_means.append(is_data.loc[mask, 'vix_30d_level'].mean())

order = np.argsort(state_means)   # 낮은 VIX → 높은 VIX 순
# order[0]=정상(Normal), order[1]=경계(Alert), order[2]=공포(Fear)

STATE_MAP = {order[0]: 'normal', order[1]: 'alert', order[2]: 'fear'}
# → state_map.pkl 저장
📌 재학습 규칙
HMM 재학습(hmm.fit)
→ STATE_MAP 반드시 재계산
→ state_map.pkl 갱신 매일 추론(hmm.predict)
→ 저장된 STATE_MAP 그대로 사용

2-3. State 분류 시각화 (검수)

states = [STATE_MAP[s] for s in hmm.predict(is_features)]
# 날짜별 State 분포 & VIX 수준과 State 일치 여부 확인
Phase 3

Walk-Forward Grid Search — θ 최적화

파라미터 공간 (θ)

📌 BTC/USDT 무기한 선물 기준 — 레버리지 롱/숏/중립, 음수 = 숏 포지션

+2.0 = 2배 롱  |  +1.0 = 1배 롱  |  0.0 = 중립(현금)  |  −1.0 = 1배 숏  |  −2.0 = 2배 숏

param_grid = {
    'p_fear_min':   [0.55, 0.65, 0.75, 0.85],   # 공포 State 확정 posterior 최솟값
    'p_alert_min':  [0.50, 0.60, 0.70],           # 경계 State 확정 posterior 최솟값
    'lev_fear':     [-2.0, -1.0, -0.5, 0.0],      # 공포 시 레버리지 (숏 허용)
    'lev_alert':    [-0.5, 0.0, 0.5, 1.0],        # 경계 시 레버리지
    'lev_normal':   [1.0, 1.5, 2.0],              # 정상 시 레버리지 (롱)
    'max_leverage': [1.0, 2.0, 3.0],              # 절대 레버리지 상한 (청산 방지)
}
# 총 조합: 4×3×4×4×3×3 = 1,728가지
# 계산 부담 시 lev_* 후보 축소 또는 random search 병행 권장

목적함수

📌 선물 전용 비용 항목 추가: 펀딩비 + 레버리지 증거금 비용
def objective(returns, n_trades, leverage_series, funding_series):
    """
    returns        : 일별 전략 수익률 (레버리지 반영)
    n_trades       : 포지션 전환 횟수
    leverage_series: 일별 레버리지 절댓값 시리즈
    funding_series : 일별 펀딩비율 (8h × 3 합산)
    """
    sharpe = returns.mean() / returns.std() * np.sqrt(252)
    mdd    = max_drawdown(returns)

    # 거래비용: 선물 taker fee 4bp (편도)
    trade_cost = n_trades * 0.0004

    # 펀딩비 비용: 보유 레버리지 × 당일 펀딩비율
    # 롱이면 funding > 0일 때 지불, 숏이면 수취
    funding_cost = (leverage_series * funding_series).sum()

    # 청산 리스크 패널티: 레버리지 > max_leverage 구간 비율
    liq_penalty = (leverage_series > param['max_leverage']).mean() * 2.0

    return sharpe - 0.5 * abs(mdd) - 0.3 * trade_cost - 0.4 * funding_cost - liq_penalty

Phase 5

일별 추론 파이프라인 (실전)

매일 미국 장 시작 전 (한국 시간 기준 밤 10:30 이전) — Binance Futures 기준:

  1. 입력: 오늘 VIX_9d, VIX_30d, VIX_3m, VIX_6m + 직전 8시간봉 펀딩비율 3개
  2. DB에서 어제 VIX 4개 로드
  3. ΔVIX 4개 계산
  4. 저장된 scaler → pca 변환 적용
  5. delta_slope 계산 / vix_30d_level 할당
  6. feature vector = [pca1, pca2, delta_slope, vix_30d_level]
  7. HMM posterior 계산 → [P(정상), P(경계), P(공포)]
  8. 최적 θ로 레버리지 신호 매핑:
    if P(공포) > p_fear_min: lev_signal = lev_fear # 예: −1.0 (1배 숏) elif P(경계) > p_alert_min: lev_signal = lev_alert # 예: 0.0 (중립) else: lev_signal = lev_normal # 예: +2.0 (2배 롱) # 절대 레버리지 상한 클리핑 lev_signal = np.clip(lev_signal, -max_leverage, +max_leverage)
  9. 현재 보유 포지션 대비 방향·크기 변경 시 주문 실행:
    lev_signal > 0 → BTC LONG (레버리지 = lev_signal) lev_signal < 0 → BTC SHORT (레버리지 = |lev_signal|) lev_signal = 0 → 포지션 전량 청산 (NEUTRAL)
✅ Step 9: 레버리지 신호 출력 → 09:30 ET 시가 기준 시장가 진입 / 청산
🔴 리스크 관리 필수 체크

① 잔여 마진 < 유지증거금 × 1.5 시 강제 레버리지 축소
② 일중 BTC 변동률 > 8% 시 포지션 즉시 재평가
③ 펀딩비율 > +0.1% (롱) 또는 < −0.1% (숏) 시 비용 알림

추후 논의 필요 항목

⚠️ 아래 사항은 결정 전까지 기본값으로 진행
  • 1
    최대 레버리지 상한 설정: max_leverage 후보 [1×, 2×, 3×] — 거래소 청산 마진율과 연동하여 안전 상한 결정 필요
  • 2
    공포 State 숏 진입 여부: lev_fear = −1.0(숏 진입) vs 0.0(중립) — 공포 구간의 BTC 반등 리스크 vs 하락 수익 트레이드오프
  • 3
    펀딩비율 이상 시 대응: 펀딩비 > 0.1% 구간에서 롱 레버리지 자동 축소 규칙 적용 여부 (비용 패널티 강화 vs 신호 무결성 유지)
  • 4
    HMM 재학습 주기: 월 1회 전체 재학습 vs 온라인 학습(누적) 유지 — 선물 시장 구조 변화(펀딩비 레짐) 반영 속도 고려
  • 5
    파라미터 탐색 규모: 1,728개 조합 전수 탐색 vs Random Search(200회) + Bayesian Optimization 2단계 방식 비교 — 계산 예산 결정 필요
  • 6
    LSTM AE 연동: HMM 공포 State 확정 시 LSTM AE 이상탐지 임계값을 동적으로 낮추어 조기 청산 트리거 강화 방안 (현재 분리 운영)
