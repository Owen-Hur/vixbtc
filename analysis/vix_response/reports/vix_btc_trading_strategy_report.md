# VIX → BTC 트레이딩 전략 가능성 분석 보고서

## 1. 분석 목적

VIX 1시간봉 변동을 시그널로 사용하여 BTC를 매매하는 전략이 수익성이 있는지 검증한다.

---

## 2. Lookahead Bias 발견 및 수정

### 2.1 최초 분석의 오류

최초 분석에서 VIX 1시간봉 변화율과 BTC 수익률 사이에 r = -0.465(장중)라는 매우 강한 상관이 관찰되었다. 그러나 이는 **lookahead bias**가 포함된 결과였다.

**오류의 원인:**

yfinance 1시간봉에서 timestamp는 bar의 **시작** 시점이고, close는 bar **종료** 시점의 가격이다.

```
bar timestamp = 10:00 → close = 11:00 시점의 VIX
```

최초 코드에서 `vix_pct`는 다음과 같이 계산되었다:

```python
vix['vix_pct'] = vix['vix'].pct_change()
```

이는 `(close[i] - close[i-1]) / close[i-1]`로, **t ~ t+1h 구간의 VIX 변화**이다. 이 변화는 t+1h이 되어야 알 수 있다.

그런데 BTC 수익률은 **t 시점부터** 측정되었다:

```python
base_price = btc.loc[ts, 'close']  # ts = bar 시작 = t
btc_1h = (btc(t+1h) - btc(t)) / btc(t)
```

결과적으로 VIX 변화(t→t+1h)와 BTC 변화(t→t+1h)가 **동일 시간 구간**에서 측정되었다. 이는 동시적 공변동(co-movement)이지, VIX가 BTC를 예측하는 것이 아니다.

### 2.2 수정된 로직

수정된 분석에서는 **이전 bar의 VIX 변화를 시그널로, 다음 bar 시작 시점에 진입**한다.

```
시그널: VIX bar[i]의 변화율 (t ~ t+1h, t+1h에 확정)
진입:  t+1h 시점 (= bar[i+1] 시작)
BTC:   t+1h → t+1h+Xm 수익률
```

코드:

```python
for i in range(len(vix_list) - 1):
    ts_signal, row_signal = vix_list[i]      # 시그널 bar
    ts_next, row_next = vix_list[i + 1]      # 다음 bar (진입 시점)
    
    entry_time = ts_next  # 시그널 확인 후 진입
    base_price = btc.loc[entry_time, 'close']
    
    # vix_pct = row_signal['vix_pct']  ← 이전 1시간 VIX 변화 (이미 확정)
    # btc_Xm = (btc(entry + Xm) - btc(entry)) / btc(entry)  ← 진입 이후 수익
```

이 방식은 lookahead bias가 없다. 진입 시점(t+1h)에 시그널(t~t+1h VIX 변화)은 이미 확정된 과거 정보이다.

## 7. 결론

**VIX 1시간봉의 과거 변화를 시그널로 사용하는 BTC 트레이딩 전략은 수익성이 없다.**

이전 1시간 동안의 VIX 변화는 그 이후 BTC 수익률을 예측하지 못한다 (r ≈ 0, p > 0.10). 이는 논문(Luo, Tsai & Yen, 2025)의 발견과 일치한다 — VIX와 BTC의 관계는 **동시적(contemporaneous)**이며, **시차 효과(lagged effect)는 없다.**

VIX 변동과 BTC 변동은 같은 시간 구간에서 함께 일어나기 때문에, "VIX 변화를 보고 BTC를 매매한다"는 전략은 원천적으로 불가능하다. 신호를 확인하는 순간 이미 BTC 반응은 끝나 있다.

### 7.1 향후 방향

VIX를 트레이딩에 활용하려면 VIX 자체를 예측하거나, VIX와 BTC 사이에 시차가 존재하는 다른 조건(예: 장외 시간, 특정 이벤트)을 발굴해야 한다. 단순히 과거 VIX 변화를 시그널로 쓰는 접근은 유효하지 않다.
